# ADR-001: single-file deck, define-once components (HF deck)

**Illustrates:** `architecture/ARCHITECTURE.md` (layer order, authoring contract) and the ADR template installed by `process/PROCESS.md`
**Source:** HF deck docs/ADR.jsonl, accepted 19 Nov

**What to learn:** one binding constraint, written before the first slide, that the skill's
architecture still follows: four layers each defined once, slides as semantic markup plus
data-attributes, no per-slide styles or scripts. The justification names what it rejected and
cites a drift already seen in the prototypes (`#lift` opacity .11 vs .14). That evidence is what
made it stick when parallel builders later felt the pull to style one slide.

How it held up: v1 (18 slides) and the accepted v2 (12 slides) were both built on it by parallel
agents. The v2 first draft kept its letter but not its spirit: builders invented slide-scoped
components (zone, mix bar, fence, cut mark…) with no art direction; see `first-draft-failure.md`.
